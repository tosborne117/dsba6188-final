RAG Agent: Streamlit + Gemini + Qdrant / Snowflake

A Streamlit app with two pages. The Chat page runs a Gemini agent that can search your PDFs. The Create vectors page turns PDFs into vectors in Qdrant or Snowflake.

Folder: Code/dsba6188_rag_agent · 2026-10-17

Your question: can the RSA key go in .env?

Yes. The app supports two methods. Use method A.

  • A. Path in .env (recommended). Set SNOWFLAKE_PRIVATE_KEY_PATH=keys/rsa_key.p8. The key stays in a file with chmod 600.
  • B. Key text in .env. Set SNOWFLAKE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----" on one line. Use this on hosts with no file system, for example Streamlit Community Cloud secrets.

Method A is safer and easier. A PEM key has many lines. In a .env file, line breaks are easy to break. Tools that print environment variables can also show the key text.

Architecture

The sidebar has two provider choices. Embedding provider (shared by both pages) and Chat provider (Chat page). Each one is Ollama (local, no quota) or Google AI Studio. You can mix them, for example Ollama embeddings with a Gemini chat model.

Both pages use rag/stores.py. The pages do not know which database is in use. The sidebar selects the backend and the collection (Qdrant) or table (Snowflake) name.

Flow 1: create vectors

  • Each chunk keeps its source file and page number. The agent uses them for citations.
  • Replace off: new chunks are added. Replace on: old data is deleted first.
  • Scanned PDFs have no text layer. The page shows a warning for them. They need OCR first.

Flow 2: chat with the agent

The model decides when to search. For a greeting, it answers directly. For a document question, it can search more than once. The chat shows each search in a collapsed "Thought for N seconds" timeline.
